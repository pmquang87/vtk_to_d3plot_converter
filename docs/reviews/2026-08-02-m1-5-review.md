# Review: milestones 1–5 implementation (2026-08-02)

Reviewed by a 17-agent workflow: 5 review dimensions (plan conformance, reader
robustness, builder/lasso correctness, test rigor, independent end-to-end
ground truth) + 12 adversarial verifications. Every finding below is anchored
to file:line and reproduced with `.venv\Scripts\python.exe`; repro scripts are
referenced where they exist.

**Verdict: REQUEST CHANGES.** The core is genuinely sound (see "What is
right"), but two critical-tier defects produce silently wrong output for
realistic inputs, plus a cluster of confirmed majors. All fixes are small and
localized; a single fix milestone (M6) covers them.

## What is right (independently verified, not taken from the walkthroughs)

- W3 end-to-end is exact: a fresh CLI conversion renders in LS-PrePost
  **pixel-equivalent to the Vortex golden** — same von-Mises legend
  (2.751e-05…2.989e+02), same min/max element attribution (elem# 770 / 213).
- Golden tests are **live, not vacuous**: a mutation smoke check (+0.02 on
  node_disp) made both W3 and zug tests fail with real numbers. By-ID joins
  are implemented exactly as mandated.
- The **wedge mapping [0,1,4,3,2,2,5,5] is correct** — proven by Gauss
  integration (exact prism volume; the documented alternative collapses to 0)
  AND the M2 LS-PrePost render was really performed (artifacts found in %TEMP%
  + the agent workspace, timestamped before the M2 commit; an earlier claim
  that this verification was faked was **refuted**).
- The **tetra mapping [0,1,2,3,3,3,3,3] is correct** — a reviewer challenged
  it; verification scanned 186,270 real tetrahedra (NHTSA Yaris + Camry decks,
  two LS-PrePost-written decks): 100% use exactly this form, zero use the
  challenger's alternative. Keep as is.
- Reader was cross-validated against meshio on the official dialect too
  (points, connectivity, IDs, TENSORS all equal); token-stream parsing is
  genuinely count-driven and line-break agnostic.
- x0 recovery (first state WITH displacement) and lasso's absolute-coordinate
  `node_displacement` semantics: both correct, confirmed by golden read-back.
- Voigt slot order [t00,t11,t22,t01,t02,t12]: correct for this dialect
  (root cause proven from anim_to_vtk.cpp:1473-75 — its 3×3 places yz at
  (0,2) and zx at (1,2); note the builder docstring misattributes this, F9).

## Critical (fix first)

**C1. Port-dialect solids get zero stress/strain — actively wrong numbers.**
`builder.py:92,102`: `has_vonm`/`has_epsp` are gated on `n_shells > 0` and
gathered with `shell_src` only. pyradioss writes real VONM/EPSP for bricks and
tetras (`anim_vtk.py:66-73`). Verified: a solids-only port model loses the
arrays entirely; a mixed solids+shells model is worse — the shell turns
lasso's stress block on and the solids are written as **all-zero stress**,
which LS-PrePost fringes as authoritative 0.0. No warning either way.
Fix: drop the `n_shells>0` gate; add solid (and beam-scalar) branches
mirroring the OFF handling (`solid_stress[i,:,0,0] = VONM[solid_src]`, eps
likewise). Add a solids-carrying port fixture test (e.g. from the
`rubber_block`/`tensile_bar` pyradioss examples).

**C2. Zero ELEMENT_IDs pass through — zug writes 342 beams all with ID 0.**
`mapping.py:133-137`: the zero-ID renumbering policy exists for NODE_ID only.
On the zug golden fixture the converted d3plot carries 342 duplicate beam
element IDs 0 (+10 zero shell IDs). Duplicate/zero IDs break element
identification and any by-ID post-processing. Found independently by three
reviewers. Fix: apply the same max+1 renumbering to ELEMENT_ID (per element
block), mirroring Vortex's `sequential()` policy; extend a zug test to assert
nonzero unique beam IDs.

## Major (confirmed by adversarial verification)

**M1. Official shell stress is element-local, silently, and the acceptance
test was weakened to hide it.** `builder.py:125-133` writes the (upper/lower)
tensors through without the local→global rotation; raw components differ from
the golden by up to 49.5% (σzz/σxz/σyz are zero). Downgraded from critical
because it IS the same physical stress (invariants match to ~5e-7: von Mises,
pressure, principals — the default fringes are exact) and the VTK input itself
is plane-stress local. BUT: the plan's raw `<1e-3` test was replaced by a
von-Mises check at 6% tolerance (~4 orders looser than the actual 9e-7
agreement), and no warning reaches the user. Fix: implement the
geometry-derived rotation (Vortex's `Anim_to_D3plot.py:700-771` is the exact
template; needs only x0 + shell_conn, both available) OR at minimum append a
report warning and tighten the invariant tolerance to 1e-4.

**M2. `2DELEM_Stress_(membrane)` and `2DELEM_Von_Mises` are not mapped —
TENSILE (the flagship robustness fixture) converts with NO stress at all,
warnings empty.** `builder.py:88-90` accepts only (lower)+(upper). The
membrane tensor is the real data (reproduces the file's own Von_Mises scalar
to 5.7e-6). Fix: accept membrane as a single-layer source (+ fall back to
2DELEM_Von_Mises synthetic-uniaxial like the VONM path); warn when a
recognized result family is present but unmapped. Strengthen the M5 TENSILE
test beyond `n_states == 20`.

**M3. Capability detection keys on state 0 only.** `builder.py:83-104`. An
array missing from state 0 but present in all others is dropped for the whole
series, silently (verified: VONM stripped from state 0 → no stress array, no
warning). Inconsistent with the all-state scans for DISPLACEMENT/VELOCITY.
Fix: detect via union over all states.

**M4. Zero-fill happens without the mandated warning.** All per-state fill
loops (`builder.py:114-194`) leave zeros (or ones, for OFF→alive) silently.
Verified: VONM stripped from state 10 → stress 0.0 at state 10 between 0.177
and 0.238, warnings list unchanged — indistinguishable from physics. Fix: one
aggregated warning per array naming the zero-filled states.

**M5. `--title` is a no-op advertised in three places.** `builder.py:38`
accepts it, nothing assigns `d3.header.title` (lasso supports it — verified
by control experiment; the header title round-trips when set). One-line fix +
one CLI test.

**M6. `element_beam_is_alive` never written.** `builder.py:181-194` covers
shells and solids only; plan requires beams too. Verified end-to-end: a beam
deleted in the VTK stays alive in the d3plot. Three-line fix using
`beam_src`; needs a beams+OFF fixture (none exists today).

**M7. Phantom zero-ID node geometry (official dialect).** The e2e reviewer
found the zug conversion renders spurious shell fans hinged on the NODE_ID==0
node that the Vortex golden does not show. Investigate how Vortex treats
cells referencing the zero-ID node and match (likely: drop or mask them).

**M8. Reader performance on real official files.** `vtk_reader.py:21`:
per-line Python token loop → 19.2 s for ONE 66 MB state (the getriebekette
class has many states). The design called for bulk numpy conversion. Fix:
read the numeric block as one buffer and `np.fromstring`-style convert.

## Minor (fix opportunistically in M6)

- Parse errors don't name the offending file (e2e proved: a truncated file in
  a 21-file series reports only "Expected 660 tokens, got 627").
- `ConversionReport`/CLI report only `<out>`, never the mandatory `<out>01`
  family file — users will ship half a d3plot.
- `--f64` has zero test coverage (manually exercised by a verifier: works).
- Dialect classifier tests `time is not None` instead of FIELD-provenance;
  "unknown" branch is dead code (downgraded from major — dialect is
  metadata-only by design decision #7).
- Q&A rulings unimplemented in the mapper: known-name ncomp strictness,
  symmetric-tensor sanity check.
- Recognized-but-unmapped official arrays (Acceleration, Contact_Forces,
  Specific_Energy, Thickness…) leave no trace in warnings.
- `lspp_check.py` wordsize probe can't distinguish 32-bit (LS-PrePost prints
  nothing for it) — returns null.
- Dropped/ignored non-matching files in directory mode are silent.
- `build_d3plot` returns a tuple vs the plan's single-value signature
  (internal-only; update the plan's interface block).
- Stale doc lines: plan.md:162 records "~5%" where the real von-Mises
  agreement is 9e-7; builder.py `_tensor_to_voigt` docstring misattributes the
  slot order to a lasso quirk (real cause: anim_to_vtk.cpp's 3×3 layout, F9
  above); `local-verification-report.md:92` still lists the wedge check as
  open.
- TENSILE's EROSION_STATUS now looks interpretable (0 at t=0, exactly 3 at
  the end) — the "semantics unverified" deferral could be revisited with a
  with-failure run.
- No regression tests for tetra/wedge/pyramid/beam mappings (fixtures are
  hex/quad/tri/line only) — commit the M2 synthetic VTK as a fixture with an
  lspp render test.
